Con una cuenta de ejGames (opcional, ligada al perfil local), el usuario tiene **amigos** con su presencia («jugando
a…»), **solicitudes**, **actividad** y un **perfil** como el de Steam: avatar con marco, fondo animado o imagen, tema
del perfil, vitrinas, nivel, insignias y comentarios.

Si tu tema pinta sus propios amigos y perfiles, decláralo en `theme.json`:

```json
"features": { "explore": true, "guides": true, "social": true }
```

y el host (el menú rápido) te pedirá que los abras:

```js
ejg.ui.onView(({ view, userId, tab }) => {
  if (view === "friends") abrirAmigos(tab);    // tab: friends | requests | activity (o null)
  if (view === "profile") abrirPerfil(userId); // null: el perfil del usuario
  if (view === "badges") abrirInsignias(userId);
});
```

Sin `features.social`, el host tiene su propia ventana: `ejg.friends.open(tab)`, `ejg.profiles.open(id)` y
`ejg.profiles.badges(id)`.

## Que se vea la cuenta

La cuenta es opcional, pero conviene que el usuario sepa que existe. El host ya enseña una vez, en cada perfil local
sin cuenta, el diálogo con lo que desbloquea («Novedad»). En tu tema, ponla a mano, como Steam: tu nombre en la
barra de arriba (con Actividad, Perfil, Amigos, Insignias… al pasar por encima) y un menú en tu foto. Sin cuenta,
esos mismos sitios invitan a crearla:

```js
const a = ejg.account.state;
if (a.enabled && (!a.linked || a.needsLogin)) {
  boton.onclick = () => ejg.account.openLogin(a.needsLogin ? "login" : "register");
}
```

## La forma rápida: la vista del kit

`/_sdk/kit/social.js` trae la lista de amigos (jugando, en línea, desconectados), las solicitudes, la actividad y la
página de perfil, con mando. Tú pones el sitio y el aspecto:

```html
<link rel="stylesheet" href="/_sdk/kit/social.css" />
```

```js
import { createSocialView } from "/_sdk/kit/social.js";

const view = createSocialView({
  ejg,
  root: document.getElementById("amigos"), // un contenedor visible, con altura
  focus,                                   // tu createFocus()
  start: "friends",                        // requests | activity | profile | badges (con userId; sin él, los tuyos)
  onExit: cerrarAmigos,                    // «Atrás» desde la lista
  onChange: () => pistas.set(view.hints()),
});

// Antes que tu propia navegación:
bindNav(focus, {
  back: () => view.nav("back") || miAtras(),
  lb: () => view.nav("lb"),  // pestañas: Amigos, Solicitudes, Actividad
  rb: () => view.nav("rb"),
  x: () => view.nav("x"),    // añadir amigo (o comentar, en un perfil)
  y: () => view.nav("y"),    // cambiar de estado
});

view.destroy(); // al salir
```

En un perfil abierto desde la lista, **Atrás** vuelve a la lista (`view.depth` dice cuántas pantallas hay abiertas).
Desde un perfil, el nivel y «Insignias» abren la página de insignias.

La **lista de amigos** se viste con variables sobre `.s-view`: `--s-fg`, `--s-muted`, `--s-accent`, `--s-bg`,
`--s-surface`, `--s-surface-2`, `--s-line`, `--s-radius`, `--s-focus` y `--s-font`, y con reglas sobre sus clases
`s-…` (`s-row`, `s-tab`, `s-btn`…).

La **página de perfil** es la de Steam pieza a pieza (cabecera de 976 px, columnas de 652 y 268 px, vitrinas con su
barra en degradado, actividad reciente, comentarios, estado, insignias y amigos a la derecha) y se ve igual en todos
los temas: sus colores son del **tema del perfil** que elige cada usuario (`s-theme-summer`, `s-theme-midnight`,
`s-theme-steel`, `s-theme-cosmic`, `s-theme-dark`…, los de Steam). Solo toma de tu tema `--s-focus` para el foco.
Se adapta sola a contenedores estrechos (una columna por debajo de 820 px).

<Tip>
Si prefieres montarlo por piezas, el kit también trae `createFriendsView` (con `tab`), `createProfileView`,
`createBadgesView`, `avatar(usuario)`
(con su marco), `levelBadge(nivel)`, `badgeEl(insignia)`, `presenceText(presencia)`, `groupFriends(lista)`,
`activityText(entrada)` y las listas `FRAMES`, `BACKGROUNDS`, `COLORS`, `BADGES` y `SHOWCASES`.
</Tip>

## La API

```js
ejg.account.state;
// { enabled, linked, username, userId, needsLogin, status, offline,
//   social: { me, friends, incoming, outgoing, blocked } }
ejg.account.onChange((state) => …);
await ejg.account.setStatus("away");   // online | away | invisible
ejg.account.openEditor();              // el editor del perfil (del host)
ejg.account.openLogin("register");     // el diálogo para crear la cuenta ("login": entrar)

ejg.friends.list;                      // [{ id, username, name, avatarUrl, frame, level, presence }]
ejg.friends.requests;                  // { incoming, outgoing, blocked }
await ejg.friends.add("ana");          // nombre de usuario o código de amigo ("485-304-036")
await ejg.friends.accept(id);          // también decline, remove, block, unblock

await ejg.profiles.view(id);           // el perfil entero (privacidad aplicada), con topFriends
await ejg.comments.list(id);           // { items: [{ id, text, at, author, canDelete }] }
await ejg.comments.post(id, "¡Hola!");
await ejg.activity.feed();             // { items: [{ id, kind, data, at, user }] }
```

- `presence.status`: `online`, `away` u `offline`; si juega, `presence.game` y `presence.since`. Los invisibles salen
  desconectados.
- `needsLogin`: la cuenta está ligada, pero la sesión caducó. `ejg.account.openLogin("login")` lleva a entrar.
- `ejg.ui.open("account")`: sin cuenta, el diálogo para crearla; con ella, sus ajustes.
- Las imágenes (`avatarUrl`, `backgroundImageUrl`, las capturas de la vitrina) llegan por `ejg-media`, con caché.
- En la actividad, `kind` es `played` (`data.minutes`), `achievement` (`data.name`, `data.rarity`), `completed`,
  `badge` o `friend`. `activityText(entrada, miId)` la pone en palabras.
