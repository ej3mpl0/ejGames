ejGames injects the SDK into your `index.html` before your scripts. Wait until the host sends the data:

```js
const ejg = await window.ejg.ready();
```

From there, everything is synchronous when the data is already in memory (`ejg.library.all`, `ejg.settings`,
`ejg.profile`…) and asynchronous when you have to ask the launcher for something (`ejg.game.details()`, `ejg.explore.search()`…).

## Events

`ejg.on(name, fn)` listens for notices from the host:

| Event | When |
|---|---|
| `settings` | the user changed a theme option in Appearance |
| `input` | the control type changed (controller, keyboard or mouse) |
| `focus-return` | a host screen closed: take the focus back |
| `visibility` | the theme stops being visible, or comes back (`{ visible }`) |

Each part also has its own `onChange` / `onState` (library, games, downloads…).

## Types

The full types are in `/_sdk/ejg.d.ts` (also inside the installation, at `sdk\ejg.d.ts`). With
`// @ts-check` and a reference to that file, your editor autocompletes the whole SDK.

<Note>
Inside the iframe, `confirm()`, `alert()` and `window.open()` do not work, and there is no network and no `localStorage`. See
[what a theme can do](/referencia/limites).
</Note>
